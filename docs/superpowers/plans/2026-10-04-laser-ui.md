# Laser Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A laser window in `pychron-ui` (and a `--laser` flavor): tray, camera, stage, laser, calibration, patterns, a pattern maker, and an emergency stop.

**Architecture:** The `LaserSystem`s move out of `LabSession` into a shared `Lasers` object with a lab-wide lease (queue or manual). `LaserSystem` gains one recursive gate, a snapshot, a camera view and a latching emergency stop, so it can be watched and stopped from other threads. A `LaserBridge` runs the blocking calls on a worker thread; widgets draw what it publishes.

**Tech Stack:** C++20, Qt6 Widgets, GoogleTest, Qt Test. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-04-laser-ui-design.md`

## Global Constraints

- Qt appears only under `apps/pychron-ui` and `tests/ui`.
- Never skip or disable a failing test. TDD: each test is seen to fail first.
- `LaserSystem::mutex_` is never held across a driver call; the gate is always taken before `mutex_`.
- `snapshot()` and `view()` never call `moving()` or `running()`.
- elctl and every existing test keep working unchanged in behaviour (a session given no `Lasers` builds its own).
- Never `git add -A configs`; `configs/examples/nmgrl/conditionals/` is not ours.
- Build/test: `cmake --build build/dev -j8 && ctest --test-dir build/dev -j8`; UI: `build/dev-ui`. Four UI tests (`test_theme`, `test_menu_hub`, `test_command_palette`, `test_brand`) fail on macOS offscreen before this work.

## Review Focus

- A queue starts in the instant between a manual command's lease check and its first driver call: the lease is taken before anything is sent and held to the end.
- Emergency stop pressed while the worker waits on a move, with commands queued behind it: the queued ones must not run afterwards.
- A script that has not yet seen the abort calls `fire_laser` after the stop: refused by the latch.
- The bridge is destroyed while a command waits on a move: the worker ends, the stage is stopped, nothing touches a dead object.
- A pattern saved over one that is running: the running one finishes on the path it started with.
