# File menu (New, Open, Save, Save As) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** File > New, Open…, Save, Save As… act on what the window in front edits (queue, script, conditionals file).

**Architecture:** `MenuHub` owns the four File items and forwards each to the action the window in front registered for that role. Windows keep owning their real actions and register them with `set_file_action`; the registered actions carry no shortcut and sit in no menu.

**Tech Stack:** C++20, Qt 6 Widgets, QtTest (`tests/ui`), build directory `build/dev-ui`.

**Spec:** `docs/superpowers/specs/2026-10-09-file-menu-design.md`

## Global Constraints

- Keys are spelled only in `apps/pychron-ui/src/shortcuts.cpp` (`TestShortcuts::no_widget_source_spells_out_a_key`).
- No two catalog entries that can be live at once share a key (`no_two_live_keys_clash`).
- An action that stays in a menu is never taken out and put back (`sync_menu`).
- Hub holds `QPointer`s to windows and their actions, never owning pointers.
- After C++ changes: `python3 tools/quality_check.py`, then the UI tests.
- Commits: Conventional Commits, scope `ui`.

## Review Focus

1. Window in front registered nothing (main window, data browser): all four greyed, and Ctrl+N still recalls the next analysis in the data browser. Test in Task 1.
2. Item triggered after the window it was enabled for left the front (palette, open menu): acts on the window now in front or does nothing. Test in Task 1.
3. Window closed and destroyed while registered: no dangling target, item greys. Test in Task 1.
4. New queue while one runs, or with unsaved edits and Cancel: queue and path untouched. Test in Task 2.
5. Open picker cancelled, or lab with no scripts or files: nothing opens, no dialog loop. Tests in Tasks 3 and 4.
