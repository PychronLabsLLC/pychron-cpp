# PI as a Person or an Organisation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PI is a person (family and given name in full, optional ORCID) or an organisation, keyed by its uuid, with no uniqueness on the name; shown "Jake Ross"; the data browser tells namesakes apart; a namesake in an entry sheet is asked about, never guessed.

**Architecture:** One clean migration (`0006_pi_identity.sql`) rebuilds `principal_investigator` with `kind`, `family_name`, `given_name`, `orcid`, `ror` and a generated `display_name`, and drops `last_name`, `first_initial` and their `UNIQUE`. The store's API follows; a PI's catalog key becomes its uuid. Entry reads sheets by "Family, Given" (T039's parser) with optional kind, ORCID and uuid columns and stops on a namesake; legacy import resolves by family name and initial, oldest of several, reported. The browser filters and facets by uuid.

**Tech Stack:** C++20, TinyORM on QtSql (PostgreSQL and SQLite), GoogleTest, Qt 6 Widgets, QtTest.

**Spec:** `docs/superpowers/specs/2026-10-13-pi-person-organisation-design.md`, agreed 2026-10-13 (owner; EarthBank's part left for the EarthBank work). Section numbers below are its.
