# Robust Logging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rotated log files, per-logger levels from TOML and at runtime, wire bytes in the debug log, crash-safe flushing, and a filterable UI log dock.

**Architecture:** A new `LogHub` in `libs/core` owns spdlog (file, stderr and bus sinks, async writer). Hub-made `Logger`s resolve levels from glob rules; legacy `Logger` constructors keep their current code path. `TraceRecorder` optionally mirrors bytes to a `<name>.wire` logger. The UI gets a ring-buffer `LogModel`, a filter proxy and a reworked `LogDock`.

**Tech Stack:** C++20, spdlog 1.15.3 (private to `pychron_core`), toml++, GoogleTest, Qt6 Widgets/Test (UI only).

**Spec:** `docs/superpowers/specs/2026-10-01-logging-design.md`

## Global Constraints

- Core (`libs/*`) stays Qt-free; spdlog types never appear in a public header; `spdlog::spdlog` links PRIVATE to `pychron_core`.
- spdlog pin: `https://github.com/gabime/spdlog/archive/refs/tags/v1.15.3.tar.gz`, `SHA256=15a04e69c222eb6c01094b5c7ff8a249b36bb22788d72519646fb85feb267e67`, `FIND_PACKAGE_ARGS CONFIG`.
- Defaults: `max_size_mb = 10`, `max_files = 5`, `default_level = info`, writer queue 8192 with `block` overflow, periodic flush 1 s, `error`+ flushes synchronously.
- File line format: `2026-10-01T14:03:22.481Z [warn] transport.serial.ig1: msg` (UTC, milliseconds).
- `Log` bus event shape, `TraceRecorder` trace-file format, and the `LogDock::append_log` / `append_line` / `line_count` / `text` signatures do not change.
- `PYCHRON_WARNINGS_AS_ERRORS=ON`: new code must build warning-free (`pychron_set_warnings`).
- Verification commands: `cmake --build --preset dev --parallel && ctest --preset dev --output-on-failure`; UI tasks use the `dev-ui` preset. Commit messages follow the repo style (`feat(logging): ...`) and end with the attribution trailer given to the session.

## Review Focus

1. `[logging.levels]` rule that is a bare name, e.g. `scheduler`: matches `scheduler` and `scheduler.jobs`, not `scheduler2` (Task 1 test).
2. Two glob rules that both match one logger: result must be deterministic regardless of TOML key order (Task 1 test).
3. Unwritable or nonexistent `dir`: hub still works with bus/stderr sinks and reports one error, never aborts (Task 3 test).
4. Log message containing newlines, `%`, `{}` or non-UTF-8 bytes: written verbatim as one record, no format-string crash (Task 3 test).
5. Logging after `LogHub` destruction or from a logger copied before `set_level`: must not crash or use freed state (Task 4 test).
