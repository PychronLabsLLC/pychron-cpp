# Noble-Gas Abundance Reduction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce He, Ne, Ar, Kr and Xe analyses below any age: discrimination, monitor interferences, absolute amounts, isotope dilution, components, named quantities, step-heat kinetics and a generic York isochron input, with the values revisioned in the store.

**Architecture:** Pure arithmetic goes into `libs/reduction` (new `noble_types.hpp` / `noble.hpp`, every value a `UFloat`), checked against an independent Python reference script. `libs/processing` applies it per gas inside `reduce_analysis`, extends the `Quantity` grammar, and adds three reference-fit targets whose results are saved as a new `corrections` revision kind. One migration (`0008_corrections.sql`) adds that kind; reference tables are `document` ref-objects and need none. Qt stays out of `libs/`.

**Tech Stack:** C++20, GoogleTest, `pychron::reduction::UFloat`, toml++ (config), TinyORM on QtSql behind `libs/persistence` only, Python 3.12 + numpy + `uncertainties` 3.2.3 for the reference script.

**Spec:** `docs/superpowers/specs/2026-10-18-noble-gas-abundance-reduction-design.md` (agreed 2026-10-18, open questions none). Section numbers below (§) are the spec's; equations N1-N34 are the spec's.

## Global Constraints

- Spec §16 order of work is this plan's phase order. The `reduced.cpp:107` tag fix (§3.3) is Task 1, alone.
- Every `libs/reduction` function is pure: no I/O, no clocks, no Qt; errors are `Result` with `ErrorKind::Config` and messages prefixed `reduction: ` (ArAr spec §6). Undefined values are absent with a `Diagnostic`, never a sentinel (§14).
- N3-N4 with `M = 0` must be bit-equal to E3 for every existing ArAr golden case (§3.2): the existing `tests/reduction/golden/*.json` are never regenerated by this plan.
- New arithmetic is checked against `tools/noble_golden/generate.py`, an independent implementation of N5-N34 on numpy + `uncertainties` 3.2.3, writing `tests/reduction/golden/noble_*.json` in the ArAr §9.3 case format; `--check` is the drift detector. Tolerances: ArAr §4.7 (rtol 1e-12 nominals, 1e-10 sigmas). Golden JSON is never edited by hand.
- One migration for the whole plan: `libs/persistence/migrations/pg/0008_corrections.sql` (develop has `0006_pi_identity`; data publishing phase 1 takes `0007_release.sql` on a parallel branch, so this plan uses 0008 and amends the spec's "0007" in Task 5). Read `libs/persistence/AGENTS.md` before Tasks 5-7 and any task adding a query. Commit footer `BREAKING CHANGE: run elctl db migrate --db <url>`.
- Masses from `default_molecular_weights()` (AME2020) for everything new; legacy `kSourceMasses` stay in the legacy `source_correction` mode only (§4.5).
- Weight is milligrams (§3.4). Units of a signal are `IsotopeData::units` (`fA`, `cps`); an amount with mismatched or unknown units is a `reduction_error`, not a number.
- Compressed spec style is for specs; this plan, code, comments and commit messages are normal prose. Commits: Conventional Commits with a component scope (`feat(reduction): ...`, `feat(processing): ...`, `feat(persistence): ...`).
- Inner loop: `cmake --build --preset dev --target pychron_<component>_tests`, then the binary with `--gtest_filter`. Static analysis (`python3 tools/quality_check.py`) after each task's C++ change and before its tests.

## Review Focus

Inputs the spec implies but no single section tests; each has its test pinned to the task named.

1. A label the mass table does not know (`mass35`, `PHHCl`) in an analysis with Ne: it must get stages through `ic_corrected` and never enter any `GasResult` or crash gas grouping (Task 3, `GasOf.UnknownLabelIsNoGas`; Task 4, `Reduced.OtherLabelsKeepStagesOnly`).
2. A `disc:Ar` row and legacy `source_correction` IC factors on the same analysis: the reduction must use neither and report `DiscriminationConflict`, not multiply both in (Task 9, `Discrimination.ConflictUsesNeither`).
3. An interference relation whose parent label is not collected in this run (`CO2` absent from a Ne run): skipped with `reduction_error` naming the relation, never applied as zero (Task 12, `Interferences.MissingParentIsSkippedAndNamed`).
4. A sensitivity stored in `mol/cps` applied to a signal in `fA`: no amount, `reduction_error` names the units (Task 15, `Amounts.UnitsMismatchGivesNoMoles`).
5. A step-heat aliquot whose last step is the only one with signal (every earlier `a_i = 0`): `F` jumps from 0 to 1, no `D/a²` at all, no NaN in the Arrhenius input and no crash in `york_fit` (Task 19, `Kinetics.AllGasInLastStep`).
